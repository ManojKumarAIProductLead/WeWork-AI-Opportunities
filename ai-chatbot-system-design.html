Full Pipeline — Request to Response

Every user message traverses eight layers before a response is returned. Each layer is independently observable and PM-governed. The model router is the single biggest cost lever; the explainability layer is the biggest product differentiator.

Pipeline walkthrough

What happens at each stage

Eight processing stages, each independently observable. The PM instruments every boundary with quality signals and cost counters.

01
Chat interface
Captures raw user message, session ID, conversation history, and device/channel context. PM owns the UX surface — what feedback mechanisms exist (thumbs, follow-up prompts), how history is windowed.
WebSocket · session store · A/B surface variants
02
Guardrail LLM
A fast, cheap classifier that runs before the main LLM. Checks for safety violations, PII exposure, off-topic intent, and prompt injection. Blocks or rewrites before the expensive inference chain runs. PM sets the block threshold — too tight and false positives frustrate users; too loose and harmful outputs escape.
Llama-Guard · OpenAI Moderation · custom fine-tuned classifier
03
Prompt assembly
Three prompt layers assembled in sequence: system (stable role/persona/rules), cached (domain knowledge, FAQs — PM decides what's cache-eligible), and user (enriched with resolved entities and conversation history). Cache hit rate is a direct cost metric — PM owns the scoping decision of what lives in the cache vs fetched dynamically.
Prompt caching (Anthropic / OpenAI) · Redis · token budget enforcement
04
MCP tool-calling LLM
An intermediate LLM that reads the assembled prompt and decides which external tools to invoke — booking APIs, member databases, calendar systems, space availability APIs. PM curates the tool registry: which tools exist, their descriptions (bad descriptions = wrong tool selection), and the max-hops policy (cost control).
MCP (Model Context Protocol) · function calling · tool use
05
Data layer — Knowledge graph + RAG + SQL
Three retrieval mechanisms work in parallel or sequenced: knowledge graph (entity relationships — "which members use which spaces near which amenities"), vector store (semantic similarity for unstructured content), and structured SQL/APIs for real-time transactional data. PM sets entity coverage SLAs and refresh cadences.
Neo4j · Pinecone / Weaviate · PostgreSQL · Kafka CDC
06
Model router + LLM tuner
Scores query complexity and routes to the cheapest model tier that can handle it. Simple FAQs go to a small/fine-tuned model; complex multi-hop reasoning goes to a frontier model. PM owns the routing thresholds and budget caps — this is the single biggest cost lever in the system. A well-tuned router can cut inference spend 40-60%.
GPT-4o · Claude Sonnet / Haiku · Gemini Flash · custom fine-tune
07
Explainability + output conditioning
Post-generation layer that conditions the raw LLM output through: user persona (adjust complexity, language), brand + tone rules (WeWork voice, register), policy + legal filters (GDPR, disclaimers, escalation triggers), and citation renderer (surfaces which knowledge graph nodes or documents grounded the answer). PM authors all non-technical configuration here.
Constitutional AI · RLHF-tuned filter · citation linker · persona config
08
Response to user
Final answer delivered with source citations, confidence indicator, and optional reasoning trace. PM defines what metadata surfaces to the user (show sources? show confidence? offer "tell me more"?) and what goes into the observability logging bus for retrospective analysis.
Streaming · citation UI · thumbs feedback · session logging

PM Perspective

Three highest-leverage decisions

Engineering can wire up every component. These three decisions require PM judgment and directly determine cost efficiency and product differentiation.

Model router — the cost lever

A well-tuned router pushing 70–80% of queries to mid-tier or small models while preserving quality parity on simple tasks can cut inference spend 40–60% with no UX degradation. The PM owns the routing threshold rules and the definition of "quality parity" — engineering can't set those without you.

Explainability layer — the differentiator

Anyone can wire up an LLM API. The persona config, brand tone rules, citation renderer, and policy filters are what make the chatbot feel like a WeWork product vs a generic wrapper. This layer needs PM-authored configuration — user segments, tone registers, legal trigger conditions — not engineering assumptions.

Prompt cache scope — the silent cost killer

Every uncached system prompt token is paid for on every single request at scale. A PM who defines what belongs in the cache (stable domain knowledge, FAQs, policy docs) vs what must be dynamic (user history, real-time availability) directly controls a significant chunk of the token bill.
